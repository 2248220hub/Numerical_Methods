Roots of x² + bx + 1 = 0 with |b| large: the textbook formula subtracts two almost equal numbers and loses almost all its digits.

Above: move b and compare the naive and the stable formula in single and double precision.

Numerical analysis is not only finding a solution: it is knowing how accurate and how reliable that solution is.

BASICThree questions for every algorithm

  1. Accuracy: how close is the computed answer to the true one, compared with the floating-point precision?
  2. Stability: are the unavoidable rounding errors kept small, or amplified during the computation?
  3. Efficiency: how many floating-point operations (flops) and how much memory does it need?

They will be asked of root finders, linear systems, optimisers, differential-equation solvers and inverse problems alike.

Newton doubles the number of correct digits per step near the root (quadratic) but needs a good start and f′ ≠ 0. For f = x² − 10x + 9, root 9 to 10⁻¹²: bisection 42 iterations, Newton from x₀ = 12: 6. x = 12.0 while True: x_new = x - f(x) / df(x) if abs(x_new - x) / abs(x_new) < 1e-12: break x = x_new x = 12.0_dp do xn = x - f(x)/df(x) if (abs(xn - x)/abs(xn) < 1.0e-12_dp) exit x = xn end do

CORECatastrophic cancellation

u=-b-\mathrm{sgn}(b)\sqrt{b^2-4ac},\qquad x_1=\frac{u}{2a},\qquad x_2=\frac{c}{a\,x_1} With b² ≫ 4ac the naive −b + √(b²−4ac) subtracts two nearly equal numbers. The stable form only adds numbers of the same sign and gets the second root from the product x₁x₂ = c/a. Measured (a = c = 1): at |b| = 1.6×10⁴ the naive small root has 100% error in float32; at |b| = 10⁸ still 25% error in float64. The stable formula stays at rounding level. u = -b - np.sign(b) * np.sqrt(b*b - 4*a*c) x1 = u / (2*a); x2 = c / (a*x1) u = -b - sign(1.0_dp, b)*sqrt(b*b - 4*a*c) x1 = u/(2*a); x2 = c/(a*x1)

Intermediate overflow: √(a² + b²) with a = b = 10²⁰⁰ is 1.4×10²⁰⁰, well inside the double range, yet a² overflows to ∞. Use hypot(a, b) (Fortran 2008: hypot, or norm2), which rescales internally. Instability can hide in any intermediate step, not only in the final formula.

COREWhy determinants are numerically dangerous

  • Scaling: det(cA) = cⁿ det(A). A 400×400 matrix with entries ~10 has |det| ≈ 10832: overflow, although the system is perfectly well behaved. Its log-determinant (1914.9) is fine.
  • Cancellation: det = Σ₊ − Σ₋, two huge sums of products that nearly cancel.
  • Small det ≠ ill-conditioned: 10⁻³·I has det 10−3n and is perfectly conditioned (Lecture 5).

Not A⁻¹ (three times more work and more rounding), not det(A). The target is an equivalent triangular system Ux = y, obtained by operations that do not change the solution.

COREForward reduction

\h{mik}{m_{ik}}=\frac{a^{(k)}_{ik}}{a^{(k)}_{kk}},\qquad a^{(k+1)}_{ij}=a^{(k)}_{ij}-m_{ik}\,a^{(k)}_{kj},\qquad b^{(k+1)}_i=b^{(k)}_i-m_{ik}\,b^{(k)}_k,\qquad i,j>k Allowed operations: scale a row, subtract a multiple of one row from another, swap rows. They change the matrix but not the solution. Cost: Σ(n−k)² · 2 ≈ (2/3)n³ flops. for k in range(n - 1): for i in range(k + 1, n): m = A[i, k] / A[k, k] A[i, k:] -= m * A[k, k:]; b[i] -= m * b[k] do k = 1, n-1 do i = k+1, n m = A(i,k)/A(k,k) A(i,k:n) = A(i,k:n) - m*A(k,k:n); b(i) = b(i) - m*b(k) end do end do

Gaussian elimination works on [A | b] together: a new b means starting again. LU stores the elimination itself — L holds the multipliers, U the reduced matrix — so b can come later.

COREThe algorithm, in place

def lu_inplace(A): A = A.copy(); n = A.shape[0]; p = np.arange(n) for k in range(n - 1): r = k + np.argmax(np.abs(A[k:, k])) A[[k, r]] = A[[r, k]]; p[[k, r]] = p[[r, k]] A[k+1:, k] /= A[k, k] # multipliers l_ik A[k+1:, k+1:] -= np.outer(A[k+1:, k], A[k, k+1:]) # trailing update return A, p do k = 1, n r = k - 1 + maxloc(abs(a(k:n,k)), dim=1); piv(k) = r if (r /= k) then; tmp = a(k,:); a(k,:) = a(r,:); a(r,:) = tmp; end if if (k == n) exit a(k+1:n,k) = a(k+1:n,k) / a(k,k) do j = k+1, n ! column-oriented: Fortran is column-major a(k+1:n,j) = a(k+1:n,j) - a(k+1:n,k)*a(k,j) end do end do

Solving with the factors

  1. Permute: b̃ = Pb (apply the recorded swaps).
  2. Forward substitution Ly = b̃: n² − n flops, no divisions.
  3. Back substitution Ux = y: n² flops.
